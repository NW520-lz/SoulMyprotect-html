项目背景

从 AI 电话到 AI 硬件的语音能力入口

灵枢文档中心定位：聚焦 AI 电话与 AI 硬件服务，覆盖网页接听、低延迟对话、知识库接入与设备语音交互。

产品矩阵
  • 灵语：企业 AI 电话能力，支持外呼 / 接待 / 会话分析。
  • SoulMy：AI 硬件语音服务，设备唤醒、实时对话、远程运维。
  • 网页坐席：无需传统电话人工，电脑或网页即可接听与处理来电。
  • 声驭智核：语音驱动桌面智能助理，补充企业办公与设备场景。

三类典型落地场景与价值路径

  • 为 AI 电话、桌宠、软件与设备提供语音对话接口。

优势 / 问题

优势明确，但规模化仍需持续打磨

平台优势来自技术与架构积累，挑战集中在多服务运维与场景泛化。

优势
  • Go 异步架构支撑高并发、低延迟通话。
  • WebRTC + SRTP 提供安全可靠的通信链路。
  • 开放生态与模块化服务，便于扩展与二次开发。
  • 多租户、计费、告警等企业特性齐备。
  • 硬件协议支持，覆盖 AI 设备场景。
问题 / 挑战
  • 多服务协同带来部署与运维复杂度。
  • 跨行业话术与知识库需要持续建设。
  • 多供应商 ASR/TTS/LLM 需统一体验与稳定性。
  • 高并发下的成本与合规需要精细化治理。
优势：平台级能力齐备挑战：规模化与行业化
落地建议

三阶段推进：试点、扩展、规模化

以场景驱动为主线，先验证价值，再逐步扩展到全业务流程。

阶段一 · 快速试点
  • 选定 1-2 个高价值场景（外呼 / 接待）。
  • 使用 Docker Compose 快速搭建 PoC。
  • 验证端到端通话质量与话术流程。
阶段二 · 业务扩展
  • 接入业务系统（JS 注入 / API 网关）。
  • 构建知识库与流程模板。
  • 完善权限、组织、计费配置。
阶段三 · 规模化
  • 引入告警、监控与 SLA 体系。
  • 多供应商语音模型与成本优化。
  • 拓展硬件与 AI 电话生态联动。
核心路径：场景验证 → 业务沉淀 → 规模复制建议：纳入季度 OKR
